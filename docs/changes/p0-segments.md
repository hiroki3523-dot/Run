## 変更前と変更後の違い

- 変更前: COROS の 1 記録の中にアップ・メイン・ダウンがあるか、COROS がその情報を出しているかを確かめる方法が無かった
- 変更後: ランの詳細 (COROS のラン) の一番下に「COROS のワークアウト区間を調べる (調査用)」を追加。ラップ API と FIT を読み直して、区間の情報の有無を一覧にする (保存・評価は変えない)
- 調査結果を docs/SEGMENTS.md にまとめた。ステップの無い計画でメインの失速が評価から消える問題 (S-01) を確認した

## 変更した理由

- 指示書 v3.0 第1段階「実装前の調査」: 実際の COROS のデータが何を提供するかを確かめずに、区間を自動判定できるとは言えないため

## 既存機能への影響

- 評価・取り込み・同期・認証は変更なし (fit.ts・coros.ts は変えていない。調査用の読み取りは別ファイル src/fitprobe.ts)
- 調査ボタンを押すと COROS の FIT のダウンロードを 1 回使う (1 日の上限の中から)

## 残っている問題

- S-01 (ステップの無い計画で、メインの失速が評価から消える) は未修正。区間の決め方を決めてから直す
- 実際の COROS のデータに区間の情報があるかは未確認 (ユーザーに調査ボタンを押してもらう必要がある)

## ユーザーによる確認が必要な操作

1. COROS から取り込んだランの詳細を開き、一番下の「COROS のワークアウト区間を調べる」→「調べる」→「結果をコピー」
2. 対象: 11/1 の 12km 走・1 記録の中にアップとダウンがあるポイント練・インターバル・ワークアウトを使わなかったラン
3. コピーした結果を Claude に送る
