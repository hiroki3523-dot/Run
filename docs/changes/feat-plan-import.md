# 計画の取り込み: 「貼り付け」の不具合を直し、COROS のプランの JSON をそのまま取り込めるように

## 不具合
- 計画の「貼り付け」(POST /plans/bulk) が、何を貼っても `column index out of range` で失敗していた
  (保存する値が 8 つなのに、SQL の欄が 7 つ。ステップの欄が抜けていた)

## 変更
- 取り込みでステップ (アップ・繰り返し・ダウン) も保存する
- 「置き換える」でも、走った記録と結びついた計画は消さない (その日は新しい計画を入れず、残したことを表示)
- COROS のプランを書き出した JSON (STRIDE_COROS_PLAN_EXCHANGE_V1) をそのまま読める
  - 種類: ペース走・終盤 MP → Mペース走、閾値走 → LT走、ロング → ロング走、回復 → Jog、休養 → 休養、レース → レース
  - ステップ: 繰り返し (本数・1 本の距離/時間・ペース・レスト)・アップ・ダウン。1 区間だけの日はステップにしない
  - 計画のペース: 繰り返しはその 1 本、ポイント練は速い区間、ロング走はいちばん長い区間
  - 読めないステップは除いて、そのことを表示 (推測で埋めない)
- JSON ファイルを選んで読み込める
- 登録の前に確認の一覧 (期間・件数・日ごとの種類と距離) を出し、「置き換えて登録」で確定。今日より前の日は入れない

## 変えていないもの
- COROS・Strava の連携・同期 (読むのは利用者が渡した JSON だけ)

## テスト (ローカルで実行)
- integration: 取り込みでステップを保存・置き換えでも結びついた計画は残る
- e2e: COROS 形式の JSON をファイルで読み込み → 確認一覧 (昨日の分は入れない) → 置き換えて登録
- 全体: 169 件合格・1 件スキップ (known-issues、従来どおり)
