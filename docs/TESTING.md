# 自動テスト

## しくみ

| 種類 | ファイル | 内容 |
|---|---|---|
| 計算の単体テスト | `test/*.test.ts` (evaluate・review・planner・insights・format など、以前からあるもの) | 評価・集計・計画作成などの関数を直接呼ぶ |
| API の通しテスト | `test/integration.test.ts` | テスト用データベース (メモリ上の SQLite に `migrations/` を当てたもの) に、COROS から取り込んだ形のランを入れ、実際の取り込み処理 (評価・計画との紐付け) と API を通す |
| 画面のテスト | `test/e2e.test.ts` | テスト用サーバー (画面 + 上の API) をブラウザ (Playwright・幅 390px) で開き、表示・メニュー・追加・編集・削除を操作する。`SCREENSHOT_DIR` を指定すると主要画面のスクリーンショットを保存 |
| 既知の不具合 | `test/known-issues.test.ts` | 監査で見つけた不具合の正しい動きを書いたテスト。未修正なのでスキップ (= 未検証) |

**本番には触れない**: テストは毎回まっさらなテスト用データベースを作る。`fetch` を差し替えて外へのアクセス (Strava・COROS・天気・ニュース・AI) はすべて失敗させ、Strava・COROS への接続が起きていないこともテストで確かめている。

**実行**: GitHub Actions の「テスト」(`.github/workflows/test.yml`) が、PR を作る/更新するたびと main に入ったときに動く。結果は PR の「Checks」と、Actions の実行ページ (Summary にレポート、Artifacts に `stride-review` の zip) で見られる。手元では `npx vitest run` (Node 22 以上)。

## 確かめていること (依頼の項目ごと)

| 項目 | テスト | 方法 |
|---|---|---|
| 各画面の正常表示 | e2e: ホーム・計画・実績 (一覧/日/週/月)・ランの詳細・レース一覧・レース詳細・大会を探す・シューズ・設定・週間天気 | 画面のエラー (JavaScript の例外) が無いこと、エラーのカードが出ないこと (週間天気・未連携の案内は除く) |
| 画面の横はみ出し | e2e: 上の画面 (幅 390px) | 横スクロールが出ないこと。レース詳細は既知の不具合 K-03 でスキップ |
| ナビゲーション | e2e: 下のメニュー 6 つ・戻るボタン | 押した画面に移り、メニューの選択が切り替わる |
| ボタン・入力・保存・編集・削除 | e2e: シューズ (追加・編集・削除)・レース (追加と目標タイム)・計画 (追加・削除)・ふりかえり (保存) / integration: 計画・レース・シューズの API | 画面で操作し、データベースに反映されたかを API で確かめる |
| 計画と実績の紐付け | integration: 自動で紐付け・同じ日に 2 つ・計画なし・手動の付け替えと解除・計画を消しても実績は残る | |
| ランニング評価の計算 | integration: 11/1 の 12km 走 (12.01km・53:50 → 4:29/km・サブ3と比べない・ピッチで減点しない・大会 7 日前の準備) / evaluate.test.ts | |
| 日次・週次・月次集計 | integration: 距離・本数・週の 7 日・月 / review.test.ts | |
| レースの目標設定・ペース表 | integration: 目標・状態の変更・削除 / e2e: 画面から目標タイムを入れる・ペース表に 4:30 前後が出る | |
| シューズの登録・走行距離集計 | integration: 初期距離 + 紐づいたランの合計・付け外し・削除しても実績は残る | |
| 主観評価の保存と分析への反映 | integration: 未入力は保留・入力すると余裕度と照らし合わせに出る・範囲外の値の丸め / e2e: 画面から保存 | |

## 確かめていないこと (未検証)

- COROS・Strava との実際の連携 (認証・Webhook・同期)。変更しない方針のため、テストでは外への接続を止めている
- 天気・ニュース・大会情報の読み取り・AI コーチの答え (外部サービス・AI の結果に依存)
- 通知 (Bark など) の送信
- 定期実行 (毎分・毎朝) の動き
- 計画のエディタの細かい操作 (ステップの組み立て・ドラッグでの入れ替え・ホイール入力)・スライドでの状態変更・画像の保存
- 本番のデータでの見え方 (テスト用データだけで確かめている)
- iPhone の Safari での表示 (テストは Chromium)
