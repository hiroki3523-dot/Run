# サブ3ランナー用 個人トレーニングアプリ 要件定義

## 1. 目的
フルマラソン 3:00 切り（平均 4:15/km 以内）を狙う 1 名のランナーが、
Strava の実績を自動で取り込み、計画との差分・質を毎日把握できるようにする。

## 2. 利用者・前提
- 利用者は本人 1 名（マルチユーザー不要、認証は簡易でよい）
- 走行記録は Garmin 等 → Strava に自動同期される前提
- タイムゾーン: Asia/Tokyo

## 3. 機能要件

### F1. Strava 連携
- OAuth2 で本人アカウントを認可（scope: `read,activity:read_all,profile:read_all`）
- access token（6 時間）を refresh token で自動更新
- Webhook（Push Subscription）を登録
  - GET: `hub.challenge` を 2 秒以内に返す検証
  - POST: `object_type=activity` の `create` / `update` / `delete` を受信
  - 受信後すぐ 200 を返し、詳細取得・評価は非同期で行う（Strava は 2 秒以内の応答を要求）
- 新規ランの詳細（splits, laps, 平均/最大心拍, ケイデンス, gear_id）と streams（time, distance, heartrate, cadence, velocity_smooth）を取得
- `sport_type` が Run / TrailRun / VirtualRun のみ対象
- 過去データの初回バックフィル（任意期間）

### F2. ラン評価
計画メニュー（種別・目標ペース・目標距離）と実績を突き合わせて 100 点満点で採点し、コメントを生成。
- ペース評価: 種別ごとの目標ペース帯（例: M ペース 4:10–4:16/km）に入っている割合、ラップのばらつき（変動係数）、後半の失速/ネガティブスプリット
- 心拍評価: 種別ごとの目標ゾーン（Easy は Z1–Z2、M は Z3 上限〜Z4 下限 等）滞在率、心拍ドリフト（前半/後半のペース対心拍比の差、5% 超で警告）
- ケイデンス評価: 平均 spm、目標（既定 180）との差、ペース帯別の推移、後半の落ち込み
- 総合: 種別ごとに重み付け（例: ポイント練はペース重視、Easy は心拍上限遵守重視）
- 計画が無い日のランは「フリーラン」として心拍・ケイデンス中心で評価
- 閾値（最大心拍、LTHR、目標ケイデンス、ゾーン）は設定画面で変更可能

### F3. 通知（スマホ）
- 毎朝 7:30 JST: 今日のメニュー（種別・距離・目標ペース・心拍上限）、直近 7 日の走行距離、次のレースまでの日数
- ラン後: Strava 同期を受けて数十秒以内に評価（スコア・各指標・一言コメント）
- 通知のリンクからアプリの該当画面を開ける

### F4. レース管理
- レース一覧: 名称、日付、距離（フル/ハーフ/10K/その他）、目標タイム、優先度（A/B/C）、結果タイム
- 目標タイムから目標ペースを自動計算
- 結果は該当日のアクティビティと紐づけ

### F5. 計画と実績
- 日単位の計画メニュー登録（種別: Easy/Jog/LT/Interval/M/Long/Race/Rest、距離、目標ペース帯、メモ）
- 週単位でテンプレートを複製して入力できる
- 実績（Strava）と計画を日付で自動紐づけ
- 週/月の計画距離 vs 実績距離、達成率、ポイント練の消化状況を表示

### F6. シューズ管理
- シューズ登録（名称、用途: 練習/ポイント/レース、上限距離 既定 700km）
- Strava の gear_id で自動紐づけ、または手動割当
- 累計距離、残り距離、上限 90% 到達で通知

## 4. 非機能要件
- 運用コスト: 月 0 円〜数百円程度
- 常時稼働の HTTPS エンドポイント（Webhook 受信のため）
- 定時実行（Cron）
- データ量は小（年 300〜400 アクティビティ）
- スマホで見やすいレスポンシブ UI（PWA 化できると良い）
- シークレット（Strava client secret、トークン）はサーバー側にのみ保存
- Strava API レート制限（15 分 100 / 日 1,000 リクエスト・アプリ単位）内に収まる

## 5. 対象外（初期版）
- 複数ユーザー対応、ソーシャル機能
- AI による計画の自動生成（後日検討）
