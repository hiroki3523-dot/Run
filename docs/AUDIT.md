## 5. 修正したときに、ほかに影響しやすい箇所

| 箇所 | 理由 |
|---|---|
| 保存される評価 (`activities.evaluation` の JSON) の形 | 日・週・月の評価、目標への現在地、マラソン適性、シューズの相性が `json_extract(evaluation, '$.eff_type' / '$.hr.details.drift_pct' / '$.pace.details.half_diff_s' / '$.form.score' / '$.role')` で直接読んでいる。名前を変えると、それらが黙って空になる |
| `ingestActivity` (評価して保存する処理) | Strava の Webhook・COROS の取り込み・過去データの取り込み・計画の編集・再評価のすべてから呼ばれる。評価の中身を変えると全経路に効く (連携処理そのものは変えなくても) |
| `avg_cadence_spm` の意味 (両足の spm) | 8 か所で使い、2 倍するかどうかがそろっていない (K-01) |
| kv のキー (`fb:`・`snap:`・`cond:`) | 分析・適性・AI コーチ・バックアップが同じキーを読む |
| `public/app.js` の共通の関数 (`api`・`openDialog`・`pace`・`km`・`route`) | 1 ファイル 3,700 行で全画面が共有している。PR #113 の `openDialog` の変更も全ダイアログに効く |
| 設定 (`settings`) の形 | 評価・計画・天気・連携が同じ設定を読む |
| 大会の状態 (`status`) と優先度 (`priority`) | 絞り込み条件が API ごとに違う (C-06) |

## 6. 安全面のメモ

- `/api/*` はトークン (Bearer) で保護。トークンはブラウザの localStorage に保存している。
- カレンダー購読 (`/cal/:sig/sub3.ics`) はトークン無しで読めるが、推測しにくい署名つきの URL。
- Webhook は Strava の検証トークンと選手 ID を確認している。
- バックアップの読み込みは、許可したテーブル・列だけを書き込む (列名はデータベースの定義から取っている)。
